# REQ-后台开关管理（生成引擎开关进管理后台）

> 状态：**核心方案已确认**（D1 已拍板：以 `sys_config` 表为准、项目 config.json 快照不动；D2/D3 按推荐执行），待开发
> 创建：2026-10-18
> 关联：`docs/TECH-后台开关管理.md`（技术方案，同批评审）

## 1. 背景

墨造生成引擎目前有 **94 个功能开关**（`novel_gen/config.py` 的 `FEATURE_FLAGS` 注册表，memory / writing / review / guard 四模块），控制记忆回填、正文生成、审校质检、成本防护等全部行为。当前修改开关只有三条路径，全部不满足运营需要：

| 现状路径 | 做法 | 问题 |
|---|---|---|
| 改代码默认值 | 改 `config.py` 注册表 → 发版 | 需重启/重建镜像；**存量项目 config.json 已快照旧默认值，改默认值对存量项目不生效**（决策史 2026-09-30 / 2026-10-18 两次记录"存量项目不写迁移"） |
| 手改项目 config.json | 逐项目改 `projects/<id>/config.json` | 服务器上逐本手改，易错、无审计、无法批量 |
| 环境变量 | `AGENT_GUARD_*` | 仅 guard 模块可用；容器级配置，改完要重启容器 |

同时，站长后台已有 `GET /api/admin/settings` 但**只读展示**定价/返佣/健康状态，无任何可编辑的开关管理能力。每次调参（如临时关闭某个重写开关排查问题、调整状态抽取频率降成本）都要改代码或登服务器，成本高、风险大、不可审计。

## 2. 目标

1. 管理账户后台新增「系统设置」板块，**可视化查看 + 修改全部生成引擎开关**（含 guard 阈值）。
2. 修改后**对后续所有项目的生成实时生效**——新项目、存量项目、续写、重生成、批量、扩写全部覆盖，**无需改代码、无需重启、无需发版**。
3. 不破坏既有架构约束：`FEATURE_FLAGS` 注册表仍是默认值唯一事实来源；项目 config.json 快照机制保留；novel_gen 保持不依赖 webapp；修改留审计（谁改的、何时改的）。
4. 权限隔离：仅站长（`is_admin`）可读可改，普通用户接口层 403、前端不可见。

## 3. 需求边界

### 3.1 本期能做（范围）

| 项 | 内容 |
|---|---|
| 开关范围 | `FEATURE_FLAGS` 注册表全部 94 条：memory（24）/ writing（21）/ review（41）/ guard（8，含 max_loops / max_tokens / scene_limits 阈值） |
| 后台操作 | 分组浏览（名称/说明/当前值/默认值/修改人/修改时间）、布尔 switch、数字 input-number、字符串/枚举输入、批量保存 |
| 生效方式 | 全局运行时覆盖（见 3.3 决策点 D1，推荐 A） |
| 审计 | `sys_config_log` 记录每次修改（key/旧值/新值/管理员/时间） |
| 校验 | 类型校验 + 范围校验（如 max_loops≥1、阈值 0-100），非法值拒绝保存并提示 |

### 3.2 本期不做（边界）

| 不做 | 原因 / 去向 |
|---|---|
| webapp 业务参数（定价 `PRICE_PER_10K`、返佣 `AGENT_DISCOUNT/COMMISSION_RATE/COMMISSION_BASE`、注册赠金 `FREE_REGISTER_BONUS`、登录限流等） | 涉及资金结算（P0），改动需单独走结算回归；列为二期，见 §7 |
| 项目级差异化开关（每本书单独改开关） | 现有 config.json 快照机制已支持，后台本期管"全局"，不做 per-project 管理界面 |
| 开关变更历史查询页 | 日志表先落库，查询界面二期 |
| 新增开关的能力（在后台动态创建新开关） | 开关由代码注册（AGENTS.md §11.3：新增开关先注册 FEATURE_FLAGS），后台只管理已注册开关 |
| 修改后立即打断正在运行中的生成任务 | 后台值在每次生成任务启动时读取；运行中的任务按启动时快照执行完毕，下个任务生效 |

### 3.3 待确认决策点（评审关口，缺一不可）

**D1 · 生效范围 —— ✅ 已确认（2026-10-18，用户拍板）**
- **方案 A（确认执行）**：全局运行时覆盖——后台保存的值对所有项目生成**实时生效**（含存量项目），最高优先级。用户明确约束：**开关统一收敛存储到 `sys_config` 表、以表中数据为准；每本书的 config.json 快照不动（不迁移、不改写）**。
- 动机（用户原话）：避免之后新增开关时，历史项目 config.json 缺字段导致行为不一致——表成为唯一运行时权威后，**新增开关经注册表 seed 自动入表（取默认值），历史项目生成时同样遵循表值**，天然规避"存量项目不生效"类问题。
- 技术落点：覆盖只在 `_open_pipeline` 内存态合并，**不写坏项目 config.json**（项目快照值保留，供未来 per-project 扩展）。

**D2 · 是否含 webapp 业务参数**
- 按推荐执行：**本期只做生成引擎 94 开关**；定价/返佣等业务参数二期单独做（涉及结算 P0，须全量跑 `tests/test_settle.py` + 端到端冒烟）。

**D3 · guard 参数优先级（后台 vs 环境变量 `AGENT_GUARD_*`）**
- 按推荐执行：**后台配置（表） > 环境变量 > 项目快照 > 注册表默认**。后台改了就要生效；环境变量仍是部署层兜底（表未设置时生效）。

## 4. 方案要点（概要，详见 TECH）

1. **存储**：MySQL 新增 `sys_config` 表（key/value/group/type/label/desc/updated_at/updated_by）+ `sys_config_log` 审计表；`webapp/db/config.py` 子模块提供读写（SQL 只进 db 层）。
2. **后端接口**：`GET /api/admin/config`（分组列表，含默认值来源标注）+ `PUT /api/admin/config`（批量保存，类型/范围校验 + 审计入库），均挂 `_require_admin`。
3. **生效注入**：`webapp/core.py` 的 `_open_pipeline` 内、`store.load_config()` 之后调用 `_apply_global_overrides(cfg)`（从 DB 读全局覆盖，内存覆盖 cfg，**不落盘**），一次性覆盖全部 15 个生成入口（生成/大纲/批量/续写/重生成/扩写/重跑）。
4. **前端**：`Admin.vue` 新增「系统设置」tab，按模块分组渲染开关（switch / input-number / select / input），保存走 `api/admin.js` 封装。
5. **降级**：DB 读取失败时跳过覆盖（走既有默认值链），不阻塞生成，logger 留痕（§11.6）。

## 5. 验收标准

1. 管理后台「系统设置」tab 展示全部 94 个开关，按 memory/writing/review/guard 分组，含名称、说明、当前值、代码默认值、修改人、修改时间。
2. 布尔/整数/浮点/字符串/枚举类型正确渲染并可保存；非法值（如 `max_loops=0`、阈值越界、非布尔）被后端拒绝并提示，不入库。
3. **实时生效（关键验收）**：
   - 改 `state_extract_frequency` → 新建项目生成，行为按新值（如改为 1 = 每章 LLM 抽取）；
   - 改 `book_memory`（True→False）→ **存量项目**重新生成/续写，行为按新值（book_memory 全跳过）；
   - 改 guard `max_loops` → 超限行为按新值。
4. 项目 config.json **未被后台保存动作改写**（覆盖仅内存态）；存量项目快照值仍在。
5. 权限：非管理员调用接口返回 403；普通用户前端看不到「系统设置」tab。
6. 审计：每次保存写入 `sys_config_log`，含旧值/新值/管理员/时间。
7. pytest：新增用例（db 读写/类型校验/覆盖注入/权限），相关 P0/P1 文件回归全绿；端到端冒烟（建书→生成→开关生效验证）通过。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 覆盖注入点遗漏，某入口不生效 | 覆盖只做在 `_open_pipeline` 一处（已确认 15 个入口全部经过它）；TECH 列出入口清单，测试覆盖续写/重生成/批量三条路径 |
| 后台改坏开关值导致生成异常 | 类型 + 范围校验拒绝非法值；DB 读取失败静默降级走默认值链（§11.6 留痕）；每次修改可审计、可回改 |
| 与"项目 config.json 快照"机制冲突 | 明确优先级链（后台 > 环境变量 > 项目快照 > 注册表默认）；覆盖只在内存，不落盘，项目文件保持权威快照 |
| guard 环境变量与后台互相覆盖 | 决策点 D3 拍板后按固定优先级实现，文档记录 |
| `quality.py` 等大文件新增逻辑超红线 | 本期改动面在 webapp（db/config.py + admin.py + core.py 注入）+ 前端，**不新增 novel_gen 业务逻辑**，无大文件风险；core.py 注入函数保持 <50 行 |
| 保存并发（两个管理员同时改） | 批量保存整体更新 + 时间戳乐观锁（可选）；一期简单处理：以最后保存为准，审计留痕 |
