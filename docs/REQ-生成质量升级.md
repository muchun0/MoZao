## 一、背景

墨造生成质量体系现状（2026-09-28 代码核实）：



* **已具备业内较深的质量规则体系**：六角色多智能体编排（调研 / 大纲 / 写手 / 审校 / 读者 / 风格师）、四层记忆（L1 设定库 / L2 卷摘要 / L3 近章大纲 / L4 前章摘要）、五套常驻提示词（反套路 / 人物立体化 / 番茄纪律 / 去 AI 味 / 结局硬要求）、高质量模式的场景级生成 + 动态模块 + 参数分层、四步改稿器、9 维编辑质检、每 3 章一致性校验、读者视角三问、章级 QualityChecker（1 次自动重写）、防重复检测。

* **核心短板（代码定位）**：

1. **记忆有损**：`pipeline/memory.py` L4 只回填最近 5 章一句话摘要 + 上一章结尾 120 字（`stages.py::_prev_tail`）；人物卡静态全量注入、不随剧情更新 → 长文 "人设漂移、前文事实错乱"。

2. **校验靠事后**：`pipeline/reviser.py` 中改以上只记录不自动改；`pipeline/quality.py` 只重写 1 次；无整本级终审；无 AI 痕迹量化指标。

3. **反馈不闭环**：`review.json`（章级自校验 + 单章改稿 + 读者审校）已在工具面板「改稿建议」按章可见，但 `verify_issues.json`（每 3 章一致性校验 / 读者视角三问 / 编辑审稿 score・弃书风险）与质检得分无 UI 入口，且无全书级聚合视图；`agent_trace` 有数据底座但缺质量聚合报表。

本轮对标竞品（Sudowrite / NovelAI / 妙笔神书 / 笔灵 / 学术方案 SCORE・Magnet /few-shot 锚定）整理 11 项升级需求，按优先级 P0/P1/P2 划分。

## 五、逐项需求详述

### P0-1 前文直读：摘要 + 近章正文直读

**问题现状**：`memory.build_context()` L4 仅回填最近 N 章的一句话摘要（默认 5 章），正文衔接只有上一章结尾 120 字（`stages.py::_prev_tail`）。一句话摘要丢细节（具体对话、动作、物品、位置），导致后续章节引用前文事实时人设 / 剧情漂移。

**方案要点**：



1. L4 升级为「最近 N 章摘要 + 最近 1-2 章正文直读」：

* 最近一章：正文全量（单章 2500 字 ≈ 3-4K token，DeepSeek 64K / 豆包 128K 上下文可承受）

* 前一章：正文前 50% 或最近 800 字（可配置）

1. 直读长度按 provider 上下文窗口与 `memory_window` 自适应，新增 `memory.direct_read_chapters`（默认 1）与 `memory.direct_read_chars`（默认 2000）配置项。

2. 摘要与直读正文二选一兜底：上下文预算不足时先砍直读、保摘要。

**涉及文件**：`novel_gen/pipeline/memory.py`、`novel_gen/config.py`。

**验收标准**：



* [ ] 生成第 N 章时，prompt 的 L4 层实际包含第 N-1 章正文片段（日志 /trace 可查）

* [ ] 同场景对比（纯摘要 vs 摘要 + 直读），前文细节引用准确率提升（人工抽查 5 处细节）

* [ ] `direct_read_chapters=0` 时行为与现状完全一致（回归开关）



***

### P0-2 人物动态状态跟踪

**问题现状**：人物卡（`World.characters`）静态生成后不再更新。谁在第几章受伤、谁与谁关系恶化、谁掌握了什么线索，后续章节可能错乱（如伤者第二天健步如飞、已决裂的两人突然同行）。

**方案要点**：



1. 新增「人物状态快照」结构（存 `projects/<id>/character_states.json` 或并入 world.json）：

* 字段：人物名 / 当前位置 / 身体状态 / 情绪状态 / 关键关系变化（与谁、何时、何事）/ 新得信息与线索 / 当前目标 / 出现章号

1. 更新时机：每章正文落盘后（`stages.py` 章后钩子），优先**确定性规则抽取**（正则匹配人名 + 状态词），规则未覆盖时**低成本 LLM 抽取**（复用章摘要，temperature=0.3，max\_tokens 小）；失败降级为跳过，不阻塞。

2. 注入：状态快照作为 L1.5 层插入 `memory.build_context()`，只注入**本章预计出场人物**的状态（配合 P1-3 裁剪）。

**涉及文件**：`novel_gen/store/schemas.py`、`pipeline/memory.py`、`pipeline/stages.py`、`pipeline/templates.py`。

**验收标准**：



* [ ] 连续生成 10 章，人物身体 / 关系 / 线索状态在后续章节描述中无冲突（抽查）

* [ ] `character_states.json` 每章更新且字段完整；更新失败时生成不中断

* [ ] 状态快照注入后，prompt 中该人物的状态描述与最近章摘要一致



***

### P0-3 全书质量报告（合并改稿 + 校验 + 聚合视图）

**问题现状（2026-09-28 代码核实）**：



* 已有可见部分：`GET /api/projects/{id}/review` 读取 `review.json`，工具面板「改稿建议」按章展示：状态（已自动改 / 待人工处理 N 处 / 无问题）、追更欲评分、读者感受、问题清单（级别 / 类型 / 位置 / 详情）——**review.json 并非用户不可见**。

* 真正的缺口：

1. `verify_issues.json`（每 3 章一致性校验 / 读者视角三问 / 编辑审稿 score・弃书风险，见 `store/project.py::verify_issues_path`）**不在任何 UI 入口**，校验发现的问题用户看不到；

2. `review.json` 中的 `quality_check.score / passed`（质检得分）未在前端渲染；

3. **无全书级聚合视图**：问题类型 TopN、弃书风险分布、每章得分趋势、伏笔回收核对均无；

4. 能力无法形成「AI 审稿」卖点（历史竞品分析 09-24 已点名）。

**方案要点**：



1. 后端：扩展质量报告接口（聚合 `review.json` + `verify_issues.json` + 全书统计），返回：

* 每章：质检得分 / 问题清单（类型 + 详情 + 级别）/ 是否自动改稿 / 读者追更欲评分 / 弃书风险（`reader_churn_risk`）

* 全书：问题类型 TopN、弃书风险分布、每章得分趋势、伏笔回收核对（可先出问题清单，统计随后）

1. 前端：工具面板「改稿建议」升级为「质量报告」视图（或 `ProjectDetail.vue` 新增入口），补齐校验数据与质检得分，列表与详情可切换。

2. 性能：全书统计聚合时按项目缓存（仿 `meta.json` 模式），章节未变化零重算。

**涉及文件**：`webapp/routers/projects_chapters.py`（扩展 `/review` 或新增聚合接口）、`novel_gen/store/project.py`（读 verify\_issues + 聚合方法）、前端 `ToolsPanel.vue` / `ProjectDetail.vue`。

**验收标准**：



* [ ] 质量报告页数据与 `review.json`、`verify_issues.json` 逐条一致（对账验证）

* [ ] 每章展示质检得分 / 弃书风险 / 校验问题（此前不可见数据）；全书展示汇总统计

* [ ] 无数据时页面友好降级（显示 "暂无审稿数据"）

### P1-1 单章 "人物行动表先行"

**问题现状**：正文整章一次生成，人物 "做什么 / 为什么" 由模型临场发挥，容易 OOC、剧情空转（对话不推进、主角被动）。

**方案要点**：



1. 正文生成前新增一步（开关 `action_plan_first`，普通 / 高质量模式均可启用）：

* 输入：本章目标 + 记忆上下文（L1 设定 + 本章出场人物 + 动态状态）

* 输出 JSON「人物行动表」：本章出场人物、各自目标、关键行动、情绪状态、对话意图

1. 写手基于行动表写正文：把行动表注入 user prompt（"本章人物行动表（必须落实）"），人物言行须与行动表一致。

2. 失败降级：行动表解析失败 → 直接走原流程（不阻塞、不重试）。

3. 成本：每章 +1 次小调用（max\_tokens ≤ 800），计入 `scene_limits["chapter"]`。

**涉及文件**：`pipeline/templates.py`（新增 `action_plan_prompt`）、`pipeline/stages.py`、`config.py`（开关）。

**验收标准**：



* [ ] 开启后，正文中人物言行与行动表一致率提升（人工抽查 3 章）

* [ ] 行动表解析失败时自动回退原流程，生成不中断

* [ ] 开关关闭时行为与现状完全一致

### P1-2 场景级生成下沉普通模式

**问题现状**：拆场景→逐场景→润色链路仅在 `high_quality_mode` 启用（`stages.py::_generate_chapter_hq`）；普通模式整章一次生成，长输出（2500+ 字）易前后情绪断层、局部跑题。

**方案要点**：



1. 把 `_generate_chapter_hq` 的场景链路抽为公共方法，普通模式默认开启场景拆分。

2. 触发阈值：单章目标字数 ≥ 2000 字自动拆场景（短章保持整章一次，避免小章成本放大）；`scene_split` 开关可全局关闭。

3. 高质量模式保留其特有项（动态模块 + 参数分层），普通模式只启用拆场景→逐场景→润色基础链路。

4. 成本控制：拆场景 1 次 + 场景 N 次 + 润色 1 次，单章总 token 增幅 ≤ 1.3x（对照 RD-09-15 口径）。

**涉及文件**：`pipeline/stages.py`（`ChapterWriter.write` 与 `_generate_chapter_hq` 重构）、`config.py`。

**验收标准**：



* [ ] 普通模式 ≥2000 字章节走场景链路，≤1500 字章节仍整章生成

* [ ] 单章成本增幅 ≤ 1.3x（按 token 统计）

* [ ] 场景拼接无断点（润色后通读抽检），开关关闭时行为不变



***

### P1-3 按章触发注入设定（Lorebook 式裁剪）

**问题现状**：L1 设定库（全部人物卡 + 全部伏笔）每章全量注入；人物越多 prompt 越长，无关设定稀释注意力（NovelAI Lorebook 已验证 "按关键词触发" 更有效）。

**方案要点**：



1. `memory.build_context()` L1 裁剪：

* 根据本章 goal + 上章摘要做**出场人物预测**（正则匹配人物名；预测失败则注入全部）

* 只注入预测出场人物的角色卡与相关伏笔；未出场人物不注入

1. 永不裁剪清单（最高优先级，始终注入且放 prompt 末尾）：`lock.json` 锁定项、用户强约束（背景 / 主角 / 避雷）、核心世界观一句话。

2. 注入顺序：普通设定在前、关键设定（锁定项 / 主角）在后（越靠后模型权重越高）。

**涉及文件**：`pipeline/memory.py`、`pipeline/templates.py`。

**验收标准**：



* [ ] 人物 ≥ 6 的书中，单章注入人物卡数量下降（较现状可量化）

* [ ] 锁定项 / 强约束 100% 注入且位于 prompt 末尾

* [ ] 裁剪前后同场景生成质量不下降（人工抽检 2 本书各 3 章）

### P1-4 AI 痕迹量化评分

**问题现状**：`de_ai` 只是提示词约束（`_de_ai_rules()`），成文后无量化检测，AI 味（连接词堆砌、句式对称、情绪词直白、段落结构雷同）无法度量、无法触发重写。

**方案要点**：



1. 新增确定性检测器 `pipeline/ai_taste.py`（纯函数，不调 LLM）：

* 连接词密度：然而 / 因此 / 不仅… 而且 / 值得注意的是 / 综上所述 等

* 抽象情绪词密度：愤怒 / 震惊 / 无奈 / 开心 等直白宣告

* 句式对称 / 排比模式：相似结构句连续出现

* 段落结构雷同：连续段同字数区间分布

1. 接入 `QualityChecker.check()` 作为计分项：AI 痕迹分过低（如 <60/100）时扣分并产出 "AI 痕迹" 类型 issue，触发既有 1 次自动重写链路。

2. 阈值保守配置，检测结果只作扣分项，不单独阻断生成。

**涉及文件**：新增 `novel_gen/pipeline/ai_taste.py`、`pipeline/quality.py`、`config.py`（阈值）。

**验收标准**：



* [ ] 对已知 AI 味样本（连接词堆砌 / 情绪直白）能检出并给分

* [ ] 正常正文误报率低（抽样 10 章，误报 ≤ 2 章）

* [ ] 触发重写后 AI 痕迹分提升（重写前后对比）

### P2-1 few-shot 风格范文锚定

**问题现状**：风格完全依赖文字描述（`stylist.md` + 风格角色人设 + 技能文本），无具体文风样例；调研实验表明 3-5 个样例比文字描述更能锁死文风（gennovel）。

**方案要点**：



1. `style_roles` 表新增「参考文风片段」字段（文本，2-3 段样例，管理员可配 / 用户可选填）。

2. 正文生成时（`scene_prompt` / `chapter_prompt`）把范文作为 few-shot 注入 system 末尾："【参考文风样例（模仿其选词 / 句式 / 节奏，不抄袭内容）】"。

3. 范文为空时行为不变（向后兼容）。

**涉及文件**：`webapp/db/style_roles.py`（表 / 字段）、`webapp/routers/style_roles.py`、前端工具面板、`pipeline/templates.py`。

**验收标准**：

### P2-2 全书终审（整本级一致性校验）

**问题现状**：只有章级 QualityChecker 与每 3 章局部校验，无 "全书看完后" 的最后把关：伏笔是否全部回收、结局是否呼应开篇、跨卷是否有矛盾，均无整本级检查。

**方案要点**：



1. `manager.resume()` 写完全部章节后新增终审阶段（开关 `final_review`，默认高质量模式开启）：

* 输入：全书章节标题 + 摘要序列 + 设定库（人物 / 伏笔）

* 输出 JSON 问题清单：伏笔回收核对（未回收 / 未埋设）、开篇↔结局人物弧光对照、跨卷矛盾、结局质量（对照《结局硬要求》）

1. 终审结果写 `review.json` 的 `final_review` 段；对 "大改" 级问题可选触发一次全书终改（高质量模式选项，默认关）。

2. 终审不阻塞导出（发现问题也要先交付，报告后续呈现）。

**涉及文件**：`pipeline/manager.py`（新阶段）、`pipeline/templates.py`（`final_review_prompt`）、`store/project.py`。

**验收标准**：



* [x] 终审在样例书上发现至少 1 个伏笔 / 弧光类问题（构造样例验证）

* [x] 终审结果落 review.json，前端质量报告可见（配合 P0-3）

* [x] 终审失败不阻塞导出与结算

### P2-3 动态模块随机化

**问题现状**：`templates.py::_pick_dynamic_module` 用 `chapter_no % N` 轮询选择视角 / 感官 / 节奏模块与随机小变量 —— 规律固定（每 N 章同模块循环），模型可能感知套路，动态扰动失效。

**方案要点**：



1. 改为按章随机选择 + 近 3 章去重（同类型模块不连续重复）。

2. 可选 seed 参数支持可复现（调试用，默认随机）。

3. 保持 "只做微调不颠覆基底" 的既有约束。

**涉及文件**：`pipeline/templates.py`。

**验收标准**：



* [x] 连续 10 章无连续 2 章同视角 / 同感官 / 同节奏模块

* [x] 同一 seed 下选择序列可复现

* [x] 回归：动态模块内容格式不变，prompt 注入位置不变
