# 蒸馏指南：从原始材料到 Agent Skill

> 目的：把一篇写作技巧/爆款拆解，浓缩成 300-800 字的 prompt，挂到对应 agent。

## 一、判断该挂到哪个角色

| 材料内容 | 挂到 |
|---|---|
| 题材调研、读者偏好、反套路套路 | researcher |
| 大纲结构、人物设计、节奏、伏笔、时间线 | architect |
| 句式、文风、对话、细节描写、爽点写法 | writer |
| 检查清单、避坑、审稿维度 | reviewer |
| 通用原则（"不要直白喊情绪"） | all |

## 二、提炼五步法

### 1. 删空话
- 删掉"写得好""很有感染力"这类评价
- 删掉作者的个人故事/感慨
- 删掉与具体技巧无关的过渡句

### 2. 拆成可执行规则
把"要写得有画面感"这种空话，拆成：
- ❌ 抽象："多用感官描写"
- ✅ 具体："每章至少写一次触觉/听觉/嗅觉的细节"
- ✅ 可检查："不写'他很愤怒'，写他攥紧拳头/咬后槽牙"

### 3. 保留正反例
- 正反例比规则有用 10 倍
- 每个规则配一个"改前 vs 改后"
- 例子不要长，两句话足够

### 4. 去重
- 一篇材料里反复说的同一个点，只留一次
- 跨材料重复的，合并成一条

### 5. 压缩到 300-800 字
- 太长 LLM 抓不住重点
- 太短不够具体
- 目标：贴进 system prompt 后不啰嗦

## 三、Skill prompt 模板

```
【{技巧名}】

适用场景：{什么时候用}

规则：
1. {可执行规则1}
2. {可执行规则2}
3. {可执行规则3}

正反例：
- 改前：{错误写法}
- 改后：{正确写法}

禁止：
- {常见错误}
```

## 四、测试方法

1. 在管理后台新建 skill，选对应 role
2. 新开一本小说，生成前 3 章
3. 检查：
   - 这条规则有没有真的被执行？
   - 有没有和已有 skill 冲突？
   - 会不会让文风变僵硬？
4. 不行就改 prompt，别一次加太多

## 五、反模式

- ❌ 一次塞 20 条规则 → LLM 记不住
- ❌ 用抽象形容词（"文笔优美""节奏紧凑"）→ 不如"每段不超过3行"
- ❌ 把整篇文章贴进去 → 蒸馏的意义就是压缩
- ❌ 不区分角色 → 写手的规则塞给架构师，两边都不对
